# meeting-scribe

Пользователь присылает аудио встречи (путь к файлу). Я делаю транскрипт и фоллоу-ап для участников. Интерфейсов нет, всё делаю сам.

## Процесс

1. `uv run scribe.py "<аудио>" [--name <slug>] [--terms "Имя Фамилия,Термин"]`
   - `--name`: slug папки; если тема известна заранее, задать сразу.
   - `--terms`: имена участников и термины встречи, улучшают распознавание. Постоянные — в `glossary.txt` в корне репо (по одному на строку, необязательный, в git не попадает). В MAI уходят первые 50 (phrase list через опции провайдера Azure). Scribe словарь вместе с диаризацией не принимает.
   - Результат: `meetings/<дата>-<slug>/transcript.md`, а также `transcript.json` и `raw/` (сырые ответы API). `<дата>` — дата создания файла, не обязательно встречи.
   - Повторный запуск берёт ответы из `raw/` и не платит повторно; новые `--terms` на них не действуют. Чтобы перераспознать слова, удалить `raw/words_*.json`: имена спикеров сохранятся.
   - Работает долго (минуты): запускать в фоне.
2. Прочитать `transcript.md` целиком. Определить имена спикеров по контексту (обращения, представления, роли) и тему. Если не уверен, оставить «Спикер N».
   - Если тема ясна, переименовать папку, сохранив дату: `mv meetings/<дата>-<старый> meetings/<дата>-<slug>`. Перезапускать потом только с `--name <slug>`, иначе `raw/` не найдётся и всё распознается заново.
   - Применить имена (заодно обновит заголовок): `uv run scribe.py names meetings/<dir> 1=Андрей 2="Мария (дизайн)"`.
   - Одно имя на несколько меток — нормально, если диаризация разбила одного человека.
3. Написать `followup.md` в ту же папку (шаблон ниже).
   - Кто что сказал, определять по содержанию реплик, а не по меткам спикеров: метки ошибаются.
   - Задача — только то, что человек взял на себя (согласие на поручение тоже считается). Совет или предложение — не задача.
   - Дата встречи — из слов пользователя или из записи; если её нет, дата папки с «(?)».
4. Проверить `followup.md` по транскрипту независимыми субагентами параллельно (Workflow, если доступен):
   - 3 агента пытаются опровергнуть утверждения: кратко и решения; задачи и открытые вопросы; участники и ход обсуждения;
   - 1 агент ищет пропущенные договорённости.
   Исправить найденное. На первой встрече проверка нашла 35 замечаний, в том числе чужой процесс, приписанный клиенту.
5. Ответить пользователю коротко: ссылки на файлы и суть встречи в 3–5 строк. Упомянуть сомнения: неуверенные имена, плохие куски записи.

## followup.md

Пишется для рассылки участникам. Без воды. Только то, что прозвучало на встрече: не выдумывать сроки и ответственных, неясное помечать «(?)».

```markdown
# <Тема> — итоги встречи <ДД.ММ.ГГГГ>

**Участники:** ...

## Кратко
2–4 предложения: зачем собирались и к чему пришли.

## Решения
- ...

## Задачи
| Что | Кто | Срок |
|---|---|---|

## Открытые вопросы
- ...

## Ход обсуждения
- [ЧЧ:ММ:СС] тема — суть (таймкоды ведут в транскрипт)
```

## Движки (выбраны 2026-10-08, всё через OpenRouter, ключ `OPENROUTER_API_KEY` в `.env`)

- **Слова:** `microsoft/mai-transcribe-2`. Лучший на разговорном русском по независимому бенчмарку DAI-ASR-I18N (2026-10). На нашей записи (2026-10-08) — лучший в слепом сравнении со Scribe v2 и Gemini 3.5 Transcribe: меньше всех пропускает слова и чаще всех выбран лучшим в голосовании аудиомоделей.
  - Gemini 3.1 Pro по словам почти наравне, но таймкоды у него приблизительные (одна отметка на реплику), на одном куске ответ оборвался по лимиту, работает в 5–10 раз медленнее.
  - Gemini 3.5 Transcribe теряет ~20% слов — не брать.
- **Спикеры:** `elevenlabs/scribe-v2` с `diarize`. MAI через OpenRouter диаризацию не умеет.
- **Нарезка.** Запись режется на куски около 30 минут в самых тихих местах. Целиком 2,7 ч не проходит: Scribe отвечает 524 по таймауту. Кэш назван по куску: `raw/words_<начало>-<конец>.json` (секунды).
- **Сшивка спикеров.** Кусок для Scribe начинается на 5 минут раньше, метки двух кусков сшиваются по общим словам в этом перекрытии. Голосовые отпечатки для сшивки не годятся: на записи с телефона в комнате акустика меняется сильнее, чем голоса.
- **Сбои.** Если кусок MAI упал, в нём берутся слова Scribe (WARNING, отмечено в строке «Источник»). Если упал Scribe, скрипт завершается с ошибкой. В обоих случаях перезапуск той же командой перезапросит только упавшие куски: удачные лежат в `raw/`.
- **Имена при перезапуске** сохраняются, пока метки спикеров те же. Если Scribe перезапрошен и метки изменились, скрипт сбрасывает имена и пишет об этом: `names` применить заново.
- **Слабое место — диаризация очных встреч.** Scribe дробит людей внутри куска, поэтому спикеров получается много: на встрече 2,7 ч с ~3 участниками их было 31. Это нормально. На шаге 2 свожу метки к людям по смыслу. Записи из Zoom или Телемоста размечаются гораздо лучше.
- Модели заданы константами в начале `scribe.py`. Список STT-моделей OpenRouter: `curl -s "https://openrouter.ai/api/v1/models?output_modalities=all"`, где `architecture.modality == "audio->transcription"`.
